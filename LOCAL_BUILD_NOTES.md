## 1. Prerequisites & Tooling

To build, debug, and package Tapster locally, your workstation requires:

1. **.NET SDK**: .NET 8.0 SDK (8.0.400+) or .NET 9.0 SDK.
2. **Visual Studio 2022** (v17.8+) with workloads:
   - *.NET Desktop Development* (WPF, C# 12)
   - *Windows Application Development* (Windows App SDK / WinUI 3 tools)
3. **Windows 10/11 SDK**: Build 10.0.26100.0 or 10.0.22621.0:
   - Tool paths: `C:\Program Files (x86)\Windows Kits\10\bin\<version>\x64\`
   - Required utilities: `MakeAppx.exe`, `SignTool.exe`.

## 2. Local Build Commands

### 2.1 Standard Solution Compilation
Always compile the solution using Release configuration:
```powershell
dotnet build Tapster.sln -c Release
dotnet build-server shutdown
```

> [!IMPORTANT]
> **MSBuild Worker Cleanup**: Always execute `dotnet build-server shutdown` after local builds to prevent persistent background compiler processes (`VBCSCompiler.exe`, `MSBuild.exe`) from holding file locks on generated `.dll` and `.exe` binaries.

### 2.2 Running Individual Projects
- **WPF Lightweight Native Utility**:
  ```powershell
  dotnet run --project src/Tapster.Gui/Tapster.Gui.csproj -c Release
  ```
- **Modern Fluent WinUI 3 Dashboard**:
  ```powershell
  dotnet run --project Tapster.Fluent/Tapster.Fluent.csproj -c Release
  ```

## 3. Packaging & Distribution

Tapster supports dual-track distribution:

### 3.1 Portable Single-File Executable
```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_portable.ps1
```
- Outputs standalone `Tapster.exe` into `publish/portable/`.
- Zero external runtime dependencies; can run from USB drives or portable environments.

### 3.2 MSIX Modern Package
```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_msix.ps1
```
- Compiles `Tapster.Fluent` and embeds unmanaged dependencies into `publish/msix/Tapster.msix`.
- Uses test certificate generated by `scripts/setup/create_dev_cert.ps1` for local side-loading.

## 4. Engineering & Safety Guidelines

1. **No Mixed Commits (Governance & Code)**:
   Never commit governance documents (`MEMORY.md`, `docs/HANDOVER.md`) together with production code files (`.cs`, `.xaml`, `.csproj`). Always commit them separately to prevent free-riding and preserve clean git blame history.
2. **Cancellation Token Closure Discipline**:
   Worker loops in background tasks must never re-evaluate nullable `_cts?.Token` inside tight execution loops. Always pre-capture `var token = _cts?.Token ?? CancellationToken.None;` before launching background threads.
3. **P/Invoke Memory Protection**:
   All unmanaged `SendInput` and `SetWindowsHookEx` structures must specify explicit marshaling rules and exact struct packing sizes.
